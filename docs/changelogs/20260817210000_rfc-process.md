## Decisions

rfc-process is a dual export like claims-audit and dependency-policy. The fragment states when to write an RFC and points at the skill. The skill holds id claims, the shared template, types, statuses, isolation default, and how to flatten an existing tree without renumbering.

Project bands, extra product tests, and isolation-on stay in each repository rfcs/README.md. The package names only the rfcs/ layout.

When 0001 is already a product document, the process RFC takes the next free id in the process band.

Product RFCs specify a design. New RFCs omit Describes. Version numbers belong in changelogs. Implementation notes are optional evidence. Alignment updates headers without restyling bodies unless asked. That rule stays in the skill.

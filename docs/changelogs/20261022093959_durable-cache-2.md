# Durable cache 2.0

## Decisions

Expand `amkisko/durable-cache` from a multi-instance shared-store fragment into a fragment and skill for cached and rebuildable derived state. Keep one package for process, persistent, materialized, computation, reconciled, and shared HTTP response caches because they share truth, identity, consistency, rebuild, and invalidation decisions.

Treat `durable` as a contract to establish, not a guarantee implied by a disk-backed cache or product name. If an acknowledged write has no other authoritative copy or losing an entry breaks correctness, treat the store as durable state with its own commit, recovery, and consistency contract.

Keep provider defaults and framework snippets out of shared guidance. The HTTP reference records standards and protocol boundaries, then requires current official documentation and effective behavior for one deployment.

Publish the package as 2.0.0 because its scope and installation contract change. Consumers with applicable state compose the fragment and tree the skill together. Prayers 1.30.0 carries the package release.

Publish `amkisko/engineering-audit` 2.14.3 in the same release. Keep its cross-stage evidence and ranking contract, route detailed cache lifecycle work to `durable-cache` when available, and retain a self-contained cache check when the specialized skill is absent.

## Effects

`durable-cache` now covers classification, authoritative and derived state, complete reusable identity, read consistency, durable invalidation intent, deletion replay, stale-fill races, bounded concurrent misses, rebuilds, isolation, and resource budgets.

The skill routes HTTP response caching to a focused reference covering ordinary HTTP, GraphQL, POST reads, HTTP QUERY, JSON-RPC, gRPC, Connect, and streams without freezing provider-specific behavior.

`engineering-audit` now accepts validation, version, generation, or bounded staleness as explicit read contracts instead of requiring every cached read to revalidate. Its observability mode covers stale or rejected fills, invalidation and rebuild lag, evictions, hot keys, source amplification, stored bytes, and recovery progress.

No person-facing visual surface changed. Visual assessment skipped.

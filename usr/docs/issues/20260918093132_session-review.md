## Decisions

Add a skill-only package that reviews agent sessions for repeated work, corrections, and reusable patterns. Do not compose it into AGENTS.md. Always-on compose is already over the 16 KiB house target; this procedure is on demand.

Name the package and skill session-review. The review reports findings and records recommendations. It implements a recommendation only when requested. It does not train a model. It does not edit skills, rules, integrations, or canonical preferences without approval.

Stay on this project. Window is since the last review of this kind, else the last 30 days. State which sessions were actually readable and any gaps. Harness-specific transcript paths stay in the consumer.

One incident is a hypothesis. Confirm recurrence from original transcripts. Rank only the strongest recommendations. Split project-specific from reusable.

Smallest response, one of: script or CLI, tool or adapter, shared prayer package, project convention or documentation, no action. Prefer a short script for repeatable steps. Prefer deterministic helpers over repeated model reasoning.

Durable record goes under usr/docs/issues per docs-conventions, one note per review episode. Link the previous review used to set the time window. Do not mark the review complete when evidence collection failed. Keep secrets and unrelated personal information out. Writing that record does not change skills or rules.

Later prose pass: an explicit request can authorize edits to skills, rules, integrations, or canonical preferences. This package issue is separate from review episodes.

Shared guidance recommendations name the owning prayer package. The project review stays in usr/docs/issues; work taken up in the prayers source repository gets its own issue there. Reserve usr/docs/dependencies for evidenced upstream dependency defects.

Offer pray confess as an optional acceptance or rejection signal for a reviewed distributed prayer. Use --note for a concise finding and --url when the destination must be supplied. Send only when the person's request authorizes that feedback. Keep the evidence and proposed improvement in the review note.

Before implementing an approved automation: name the replay input and a small verification gate.
